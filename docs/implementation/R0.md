# R0 Feasibility

**Exit gate:** a written report with each gate passed or explicitly accepted.
**Status on 27 Nov 2026: complete.** Arpan accepted R0 on 27 Nov with the
open checks moved to the phases that first need them:

- **Passed here:** Modal offline sandboxes on L4 and L40S, Modal timeout
  enforcement, base-model licences and label sets, and DenseNet-121 scored on
  the 20 demo images.
- **Moved to R3:** Hippius and Backblaze presigned PUT, checksum and
  If-None-Match, since R3 builds the upload path.
- **Moved to R4:** Hugging Face private download, token scope, pin upload and
  org quota, since R4 builds gates g5 and g9.
- **Moved to R5:** the DataHive checks, since DataHive isn't needed before R5.

Every moved check already has a working probe in `scripts/r0/`, so closing it
is one command once the credentials exist (see Running the moved probes).

Raw results, secrets redacted, are in [`r0_results/`](r0_results/). Each probe
is `python -m scripts.r0 <probe>` and reads its credentials from the environment
(see [`.env.example`](../../.env.example)).

## Findings that change later phases

1. **The base DenseNet has no tuberculosis or silicosis head.** Its 18 outputs
   cover pneumonia, effusion, atelectasis, edema and the like, but 2 of the 7
   conditions in the SotaRad sample, and 2 of the 4 in the demo (TB and
   silicosis, the subnet's headline conditions), map to nothing. R2's reference miner needs a fine-tuned head for
   them. Until then a TB campaign's seed leader would score near chance on its
   main label. *Decided 27 Nov:* the reference miner's `map_to_labels` returns
   0 for labels DenseNet has no output for.
2. **rad-dino and cxr-foundation are encoders, not classifiers.** A miner using
   them must train and ship a head. That fits the solution contract
   (`load_model_checkpoint`, `map_to_labels`), but the reference miner should
   stay on DenseNet. *Decided 27 Nov:* both are dropped; DenseNet is the only
   base model.
3. **Labels follow the spec's certainty rule plus status.** `definite` and
   `probable` count as positive and `possible` doesn't. The SotaRad export also
   marks some TB as `previous` (healed); the probe treats those as negative.
   The demo also uses `Normal` as a finding, which the probe reads as no
   positive label rather than as a condition.
   DataHive should confirm how `previous` will appear in `/files` findings
   before R5's label adapter.
4. **Serving is permanent on production.** The DataHive probe serves nothing
   unless `--serve N` is passed, and refuses `--serve` on a host that doesn't
   look like staging or the demo unless `--i-know-this-is-production` is set.
5. **Demo images are about 8 MB each.** They are full-size 16-bit PNGs
   (7.5 to 8.8 MB). Fetching all 20 took about 60 s one at a time and about
   23 s with 8 parallel downloads from this Mac. At that size a 100-study
   round is about 830 MB, so R5's fetch has to run in parallel, and the
   `datahive_fetch_time` budget should be checked on the Hetzner host.
6. **L4 capacity is not guaranteed.** One L4 request was refused outright and
   the next queued for about 7.5 minutes; L40S started at once. R6 must treat
   `ResourceExhaustedError` and queueing as infrastructure, not miner fault:
   retry or reschedule the entry, never score it as a crash. Eval timeouts must
   start when the container starts, not when `Sandbox.create` is called.
7. **Load time includes CUDA start-up.** On L40S, importing torch took 4.9 s
   and the first load 5.0 s; the L4 run had a warmer cache (0.8 s load). A
   `model_load_timeout` of 120 s leaves a wide margin for DenseNet-sized
   models. *Decided 27 Nov:* this startup cost is the miner's to optimise. The
   harness clock starts when it begins importing the miner's module and stops
   when `load_model` returns, so import-time work can't dodge it, while
   container start, image pull and GPU queueing never count.

8. **Fallbacks if a store or HF falls short in R3 or R4.** If a store ignores
   the signed checksum, the worker still hashes the zip after download and
   rejects a mismatch. If it ignores `If-None-Match`, unique upload keys plus
   Pareton's HEAD-before-presign check still prevent overwrites. The HF quota
   only matters once many pins accumulate, since only submissions that pass
   every gate are pinned.

## Running the moved probes

```bash
uv sync --python 3.12 --extra r0 --extra r0-models --extra dev
set -a; source .env; set +a
```

In R5, from the Hetzner validator host, once staging exists:

```bash
python -m scripts.r0 datahive --serve 20 --reset-after
```

In R3 (storage) and R4 (Hugging Face), from anywhere with the credentials:

```bash
python -m scripts.r0 storage
python -m scripts.r0 hf
```

Each probe rewrites its file in `r0_results/`; update the table above from it.
